# MCP continuation

Use connected tools; the STDIO bridge needs no extra HTTP/shell controller.
Check deployment **and** hero/cycle: a fresh usable connection does not prove
the previous journey was restored. Normal mode conceals secrets; identify
any developer simulation separately.

Navigation follows apparent road. `floor` rejects stale coordinates;
`interact: false` approaches without contact. Default navigation opens/enters
a selected door, while manual movement may only open it. Endpoint contact can
leave the hero adjacent. Stop cached plans on unexpected scripts, damage,
interactions or transitions. Flight needs adjacent-stair entry and skips 44F;
Wings differ. Shops wait for listed replies; speech settles automatically.

Use absolute persistent save paths at milestones and keep replay companions.
Normal saving requires a living hero/Hero Orb; file saves also require idle
state and closed Flight. Opaque checkpoints expire on disconnect/reset and
are limited to 64; file saves still work at capacity. File loads rebuild monster
rows, so recheck later-cycle forecasts. Replay imports replace the session on
success; failures preserve it. Validate a branch before adopting it.

Compatible worker updates preserve state. On `recovery_required: true`, old
checkpoints are gone and gameplay is blocked (`-32003`) until successful
`new_game`, `load_game` or `replay_game`. Distinguish this reset from worker
startup/I/O failure. Bridge-code changes need a reconnect. Handle JSON-RPC
`error` separately from MCP `isError`; error text need not be JSON.

First-cycle 50F Zeno is an `ending` trigger with zero contact HP cost; this does
not apply to 49F or later-cycle combat. Full [protocol guide](../../../cpp-mcp.md).
